Homework Saathi — what this is

A Hindi, voice-first homework helpline on WhatsApp for parents of Class 5 government-school children in India — deliberately not for the children. It answers from the child's actual NCERT textbook, and its output is not an answer but a sentence the parent can say out loud.

Why parents

Many of these parents left school before the class their child is now in. They cannot check a maths answer, which is exactly why they are asking. That single fact settles most feature arguments:

हम बच्चों के ट्यूटर नहीं हैं — हम माता-पिता के कोच हैं।
We are not a tutor for children. We are a coach for parents.

The hard part is not generating — it is refusing

A confidently wrong maths answer that a parent then teaches their child is far worse than "I don't know", because the parent asked precisely because they cannot detect the error. So the system is built around a refusal gate calibrated on a 150-question labelled set, and it declines rather than guesses. Try the dashed example question on the first screen — it is Class 10 algebra, and it gets refused with a reason, a way forward, and no guess.

How it works

  1. Query pre-checks Deterministic, before any retrieval or model call. Catches 36 of 50 refusable questions for free — including requests to just do the homework, which are refused on purpose.
  2. Hybrid retrieval BGE-M3 dense cosine plus IDF term overlap over 248 chunks of the real textbook. Dense-only scored 87%; the lexical signal took it to 93%.
  3. Decoys as a syllabus boundary 516 chunks from Classes 6–9 exist only to be matched against. If a question sits closer to a Class 7 page than a Class 5 one, it is out of syllabus. Without them, "is this Class 5 content?" is vacuous — every chunk in the corpus is Class 5.
  4. Generation Groq's free tier, in Hindi, against the top 3 passages.
  5. Contract validation The four parts — answer, rule, a worked example using different numbers, and the sentence to say to the child — are enforced as code. An answer that fails the contract is refused, not shipped.

Constraints this was built under

  • Zero paid APIs. Free tiers only. That is a product decision about cost-per-conversation for users who cannot pay, and a sovereignty one: Bhashini (Government of India) for voice rather than a US frontier API.
  • An 8 GB M1 laptop. It killed the 7B local vision model (980 s/page); local models cap at about 2B.
  • The textbook is © NCERT, "not to be republished." So the deployed app never ships page images. It fetches the chapter PDF from NCERT's own server at request time and renders the single page asked for.

What is not done — honestly

  • Parent discovery interviews. The riskiest assumption in the whole thesis — that parents accept "I don't know" rather than leaving — is untested.
  • Every test question is authored by me, not observed from a real parent. The retrieval numbers are optimistic until that changes.
  • Voice is wired to Bhashini but needs credentials; the browser speech API stands in meanwhile, and is honestly labelled where it is used.
  • Reading figures is built but switched off. A vision model can read a bar chart off the page (and does, in the source), but this deployment runs without that key. Questions whose answer lives only in a picture are refused with a reason instead — which is the same thing the system does for anything else it cannot ground in text.
  • WhatsApp delivery is not built. This web chat exists because the WhatsApp test number can only message pre-approved recipients — a link a stranger can open is the only demo that actually demos.

Stack

Python standard library HTTP server (no framework — a demo that needs an install step before it runs is a worse demo) · BGE-M3 embeddings · NumPy index · Groq free tier for generation · Playwright for the interface tests · zero npm.

Built by Pradyumn Awasthi as a product portfolio project. The textbook is NCERT गणित मेला (Maths Mela), Class 5, NCF-2023 — 15 chapters, 190 pages, fetched from ncert.nic.in and never redistributed.
